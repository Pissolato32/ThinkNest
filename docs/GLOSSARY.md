# ThinkNest Glossary

**Version:** 1.0
**Status:** Approved
**Scope:** Shared product, architecture, AI, and delivery language
**Last reviewed:** 2026-07-29

## Core product terms

| Term | Meaning |
| --- | --- |
| ThinkNest | AI-assisted incubation workspace for turning early ideas into structured projects, conversations, documents, and implementation packs. |
| Project DNA | The structured representation of a project's intent, constraints, maturity, decisions, and generated artifacts. |
| Incubation | The guided process of evolving an idea from initial framing through validation, documentation, and implementation readiness. |
| Implementation Pack | Exportable bundle containing the information required to hand a project to builders, stakeholders, or external tools. |
| Project maturity | A documented readiness signal describing how complete, coherent, and implementation-ready a project is. |

## AI and governance terms

| Term | Meaning |
| --- | --- |
| AI orchestrator | Coordination layer that routes user context, project state, and specialist capabilities into governed AI workflows. |
| AI specialist | Domain-focused AI behavior profile that assists with a bounded task while respecting user authority and product constraints. |
| Grill-me engine | Critical-questioning workflow that challenges assumptions and helps users strengthen weak areas of a project. |
| Provider abstraction | Boundary that allows AI providers to be exchanged without leaking provider-specific behavior into product logic. |
| Human authority | Principle that the user remains the decision maker for consequential project changes and AI output adoption. |

## Architecture and delivery terms

| Term | Meaning |
| --- | --- |
| ADR | Architecture Decision Record; an authoritative decision with rationale and implementation consequences. |
| Snapshot | Immutable or versioned representation of project state used for traceability, export, or synchronization. |
| Offline synchronization | Mechanism that allows local work to continue and reconcile safely when connectivity returns. |
| Acceptance criteria | Testable conditions that define whether a behavior is ready for release. |
| Non-functional requirement | Quality target such as performance, reliability, accessibility, privacy, security, or operability. |
