# ThinkNest — P1.4 Voz

## Escopo desta fatia

A primeira fatia de voz adiciona entrada por fala diretamente à conversa:

1. o dispositivo fornece captura de microfone ao mecanismo nativo de reconhecimento;
2. resultados parciais atualizam o campo de mensagem em tempo real;
3. o resultado final permanece editável antes do envio;
4. o envio usa o mesmo `SendMessage` existente, preservando a fila offline e o worker cloud;
5. nenhum áudio bruto é persistido pelo ThinkNest nesta etapa.

## Arquitetura

`ConversationScreen → VoiceTranscriber → SpeechToTextVoiceTranscriber → speech_to_text`

O domínio conhece apenas o contrato `VoiceTranscriber`; o plugin permanece na infraestrutura.

O refinamento assíncrono não cria um segundo caminho de conversa: depois que o texto transcrito é enviado, ele segue pelo mesmo fluxo de `SendMessage` e AI Task já existente.

## Dependência

O CI fixa Flutter 3.35.7. Por isso a implementação usa `speech_to_text 7.4.x`, compatível com o baseline atual; a versão 7.5.0 exige Flutter 3.44/Dart 3.12.

A biblioteca oferece reconhecimento nativo em Android, iOS, macOS, Web e Windows. Linux não possui suporte de reconhecimento no plugin.

## Limites atuais

- permissões específicas de Android/iOS precisam ser mantidas nos projetos de plataforma quando a scaffolding for gerada;
- não há armazenamento de áudio;
- não há refinamento separado antes do envio: o refinamento pós-envio utiliza a pipeline de IA já existente;
- testes com microfone físico continuam sendo validação de dispositivo, não substituem os testes automatizados.

## Próxima evolução de P1.4

Adicionar tratamento explícito de permissões por plataforma e, se necessário, uma etapa de refinamento assíncrono dedicada que possa corrigir pontuação/transcrição antes de transformar o texto em uma mensagem definitiva.
